## 任务卡 #24：新增岗位名称字段

状态：已完成、审查并合并。

目标：在 `/interview/new` 新增可选岗位名称 `jobTitle` 输入，让每次面试和历史记录有清晰标题，同时保持旧历史记录兼容。

范围与验收结果：

- `/interview/new` 在岗位信息 textarea 前显示可选岗位名称输入框。
- 生成问题仍只强制校验岗位信息和简历；`jobTitle` 为空时仍可继续。
- 新历史记录保存 `jobTitle`；旧记录缺少该字段时回退到岗位信息摘要，再回退到“未命名岗位”。
- Mock 示例、Mock 问题、Mock 评价和真实 AI 流程均支持可选 `jobTitle`。
- 生成问题和最终评价 API 向后兼容旧请求，问题数量和最终评价 JSON 协议未改变。
- 未引入新依赖，也未改变 localStorage 旧记录兼容边界。

非目标：

- 历史删除、清空和左栏收起/展开由阶段 25 处理。
- 不包含历史搜索、云端历史、数据库、OCR、图片识别或新 AI 流程。

## 任务卡 #25：本地历史记录管理和布局优化

状态：已完成、审查并合并。

目标：提升 `/interview/history` 的本地历史管理体验，支持删除记录、清空记录、简化左侧列表，并允许收起/展开左侧列表。

范围与验收结果：

- 支持带确认的单条删除和清空全部。
- 删除当前选中记录后自动选择剩余第一条；删空后显示空状态。
- 左侧列表显示岗位名称、时间和分数；岗位名称沿用阶段 24 的兼容 fallback。
- Mock/AI 来源保留在右侧详情，不在左侧列表展示。
- 支持收起/展开左侧列表，移动端保持可用。
- 旧历史记录、Mock 历史和 AI 历史均可正常展示和删除。
- 不影响新面试、文件导入/解析、真实 AI、Mock、评价和历史保存流程。

非目标：

- 不改 AI API、prompt、文档解析 API 或 Supabase Auth。
- 不做搜索、筛选、恢复历史 session、云端同步或数据库。
- 不新增依赖。
