## 已完成功能摘要

- 核心闭环：可选岗位名称 + 岗位 JD + 简历 -> AI 生成 6 道问题 -> 用户逐题回答 -> AI 最终评价。
- 入口与账号：主页 `/`、登录页 `/login`；受保护面试区提供简历仓库、历史记录、工作台、数据和分析、个人中心五入口导航，工作台进入 `/interview/new`。
- 简历仓库按账号在私有云端存储最多 10 份 PDF、DOCX、TXT、MD 原文件，支持上传、下载、删除及在新面试中选用；数据和分析仍为页面骨架。个人中心展示当前邮箱和登出入口，不提供资料编辑。
- 受保护面试区采用约 1200px 的响应式布局、桌面顶部五入口和手机固定底栏；工作台提供新建面试入口和静态三步引导。
- 主页：使用仅作用于 `/` 的中文无衬线字体栈和精简首屏文案；保留登录/面试/登出行为，并预留不可导航的帮助、公告占位入口。
- Auth：Supabase Auth 邮箱密码注册、登录、登出和登录态保持。
- 新面试：可选岗位名称、空输入校验、生成问题、逐题提交、一键提交全部回答、答题进度、最终评价、错误重试、开始新一轮。
- 新面试有未保存内容时，页面跳转、返回、刷新或关闭会触发浏览器离开提示，登出另行确认；最终评价成功保存后可直接离开。
- 开发效率：示例 JD/简历、Mock 问题、Mock 评价、根据当前问题填入测试回答。
- 文件输入：`.txt` / `.md` 浏览器本地导入；文本型 `.pdf` / `.docx` 通过项目后端 API 解析为纯文本。
- 简历仓库需在 Supabase 手动创建私有桶、运行仓库 SQL，并把生成的服务端令牌配置到运行环境；配置完成前上传和列表不可用。
- 历史记录：最终评价生成后保存到当前账号的 Supabase 云端，按 20 条分页且不自动删除；支持详情、单条删除、清空全部和左侧列表收起/展开。旧浏览器记录可确认后手动导入，原件留在浏览器。
- 文档：已完成多 session 协作规范、内部测试准备、轻量 docs 结构和历史归档。

技术栈、路由、目录和数据流以 `docs/ARCHITECTURE.md` 为准。

## 当前限制

- 扫描版 PDF OCR、图片简历识别或复杂文件解析。
- 恢复历史 session 到当前页面。
- 历史记录编辑和搜索。
- 用户资料编辑、OAuth、支付或权限系统。
- AI 逐步提问、多轮追问、单题即时 AI 批改。
- 语音或视频面试。
- 全站设计系统重构。

## 已知残余风险

- `/api/parse-document` 的 5MB 文件大小限制发生在 `request.formData()` 之后；超大 multipart 请求仍可能先进入 Next.js formData 解析流程并占用内存。后续如需更可靠防护，应在部署平台、反向代理或更底层请求体配置中增加更早的 body size 限制。
- 云端历史需由项目所有者在 Supabase 执行建表和 RLS SQL；配置前无法保存或读取。旧浏览器记录不会自动迁移，手动导入时须确认其可能属于曾在该浏览器使用的其他账号。
- 云端历史保存失败时评价仍在当前页面，但刷新或离开后无法恢复；浏览器离开提示会继续提醒。
- 浏览器离开提示受浏览器自身限制；部分移动端关闭或系统终止页面时可能不显示。
- 真实 AI 质量依赖 DeepSeek 返回结果和解析器容错，仍需人工观察生成质量。
