# Roadmap

## 文档职责

记录下一阶段方向、阶段索引、当前优先级和暂缓事项。ROADMAP 不复述历史阶段详情；历史方案在 `docs/archive/ROADMAP_ARCHIVE.md`，默认不读。

关联文件：

- `docs/TASKS.md`：当前任务卡和验收标准。
- `docs/HANDOFF.md`：当前交接状态。
- `docs/STATUS.md`：当前项目事实摘要。
- `docs/PRD.md`：产品边界，按需阅读。

## 当前推荐方向

阶段 1-23 已完成并合并到 `main`。阶段 23 完成了 docs 目录轻量化重构。下一步建议先由产品助理 session 讨论下一组阶段方向，再启动阶段开发 session。

当前已具备的能力摘要：

- 核心闭环：JD + 简历 -> AI 生成问题 -> 用户回答 -> AI 最终评价。
- 产品入口：主页、登录、受保护面试工作台、新面试页、本地历史页。
- 输入效率：开发 Mock、txt/md 本地导入、PDF/DOCX 纯文本解析。
- 存储边界：历史记录仍在 localStorage；文件只做一次性解析，不保存原始文件。

## 当前优先级

1. 在 `main` 上保持阶段 23 合并后的文档结构稳定。
2. 由产品助理 session 一次讨论下一组阶段方向，再拆成 TASKS 中的具体任务卡。
3. 新任务卡确定前，不启动新的阶段开发 session。
4. 开始新阶段时，从 `main` 新建对应功能分支。

## 下一阶段候选方向

- 优化已有面试流程体验。
- 增强历史记录能力，例如删除、搜索或恢复历史 session。
- 规划云端历史记录和数据库存储。
- 继续做小范围 UI/文案/错误恢复优化。

## 暂缓事项

- 云端文件存储、OCR、图片识别或复杂文件解析。
- 语音或视频面试。
- 未规划的 AI 逐步提问、多轮追问或单题即时批改。
- 用户资料页、OAuth、支付或权限系统。
- 复杂视觉重构或全站设计系统重构。

## 更新规则

- ROADMAP 只保留当前和未来，不复述历史阶段长文。
- ROADMAP 用来记录阶段级方向、阶段索引和优先级，适合一次讨论多个阶段后更新。
- 单个具体任务的目标、范围、验收标准和审查关注点优先写在 `docs/TASKS.md`。
- 阶段内开发、审查和修复一般只更新 `docs/TASKS.md`、`docs/HANDOFF.md` 和必要的 `docs/STATUS.md`，不需要每次都改 ROADMAP。
- 当新增/完成一组阶段、调整阶段顺序、改变产品方向或暂缓事项时，再更新 ROADMAP。
- 如果阶段详情变长，归档到 `docs/archive/`。
