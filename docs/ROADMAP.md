# Roadmap

## 文档职责

这个文件记录 AI Interview Simulator 的阶段计划、当前优先级、暂缓事项和决策原因。它用于帮助产品助理、前端开发、后端开发、代码审查等不同 session 对齐“接下来按什么顺序做”。

关联文件：

- `README.md`：项目入口说明，告诉新读者项目是什么、怎么运行。
- `AGENTS.md`：多 session 和 AI agent 协作规则。
- `docs/PROJECT_STATUS.md`：当前事实，记录已经完成什么、当前阶段是什么。
- `docs/PRD.md`：产品范围和需求定义。
- `docs/DEVELOPMENT_TESTING.md`：开发测试流程和开发辅助边界。

## 当前推荐方向

当前 MVP 已经跑通“岗位信息 + 简历 -> 生成问题 -> 逐题回答 -> 最终评价”。下一条主线建议是先初始化历史记录能力，而不是马上改成 AI 逐步提问。

原因：

- 历史记录不破坏当前列表式面试流程。
- 历史记录会沉淀一次完整面试 session 的数据结构。
- 后续如果改成逐步提问，也可以复用 session 数据结构。
- AI 逐步提问会同时影响前端交互、API 协议、prompt、状态管理和最终评价输入，复杂度更高。

## 当前优先级

当前优先级：

1. 先为当前分支做人工回归测试并准备 PR。
2. 下一个功能分支建议做历史记录初始化。
3. 暂不改成 AI 逐步提问。

推荐下一个功能分支：

```text
develop-mvp-history
```

第一步只建议定义和保存本地 session 数据结构，不急着接数据库。

## 历史记录初始设想

一次完整面试 session 可以先设计为：

```js
{
  id: 'local-session-id',
  jobInfo: '岗位信息文本',
  resume: '简历文本',
  questions: [],
  answers: {},
  submittedAnswers: {},
  evaluation: {},
  createdAt: 'ISO 时间',
  updatedAt: 'ISO 时间'
}
```

初始实现建议：

- 先用 localStorage，不接数据库。
- 只在最终评价成功后保存一条完整记录。
- 保存失败时不要阻塞用户看到最终评价。
- 后续再做历史列表、详情查看和恢复。

## 暂缓事项

暂不优先做：

- AI 逐步提问
- 多轮追问
- 登录注册
- 数据库存储
- 文件上传解析简历或 JD
- 语音或视频面试
- 单题即时 AI 批改
- 复杂 UI 重构

这些方向可以在历史记录基础能力稳定后再评估。

## 更新规则

ROADMAP 不应清空重写。阶段完成后应勾选完成，并调整“当前优先级”和“暂缓事项”。

如果计划变得很长，可以后续新增 `docs/ROADMAP_ARCHIVE.md` 归档旧阶段；当前项目还不需要归档。
