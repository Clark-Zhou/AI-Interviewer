# Testing

## 文档职责

记录当前长期有效的开发测试边界和核心回归路径。不要为每个阶段永久新增检查点；阶段验收以 `docs/TASKS.md` 当前任务卡为准。

## 什么时候读

修改以下内容时读本文件：开发辅助按钮、Mock 流程、登录、文件导入/解析、历史记录、AI 请求链路或测试流程。

## 测试边界

- AI agent 不安装依赖；需要依赖时告诉用户命令。
- AI agent 不默认启动 dev server，除非用户明确要求。
- 不真实调用 DeepSeek，除非用户明确要求或任务必须验证真实 AI。
- 生产环境不应显示 Mock 按钮。
- 本地历史记录只验证当前浏览器 localStorage，不假装有云端同步。

## 当前开发辅助能力

开发环境 `process.env.NODE_ENV === 'development'` 下可见：

- `填入示例 JD/简历`：填入固定测试输入，并清空上一轮状态。
- `使用 Mock 问题`：使用本地固定问题，不调用后端 API。
- `填入测试回答`：根据当前问题生成本地测试回答。
- `使用 Mock 评价`：生成本地固定评价，不调用后端 API，并复用历史保存链路。

## 核心回归清单

登录与入口：

- `/` 显示主页、登录/登出入口、面试入口和登录状态。
- 未登录点击面试入口进入 `/login`。
- 登录或注册成功后回到 `/`。
- 已登录用户可进入 `/interview`，刷新后仍保持登录态。
- 登出后回到未登录状态。

新面试流程：

- `/interview` 只提供开始新面试和查看历史记录入口。
- `/interview/new` 初始状态不显示历史记录区，也不显示问题空面板。
- `/interview/new` 显示可选岗位名称输入；岗位名称为空时仍可生成问题。
- JD 或简历为空时，点击生成问题会提示错误。
- 生成问题后展示问题列表、分类、问题文本和原因。
- 每题可单独提交，也可一键提交全部回答。
- 所有题提交后才能生成最终评价。
- 最终评价展示总分、总结、优势、风险点、建议、逐题反馈和后续练习。
- 生成问题或最终评价失败后可重试。
- `开始新一轮` 清空当前输入、问题、回答、提交状态、评价和提示，但不删除历史。

文件输入：

- JD 和简历输入区支持 `.txt` / `.md` 本地导入。
- JD 和简历输入区支持文本型 `.pdf` / `.docx` 后端解析。
- 导入或解析成功后文本进入现有 textarea，用户仍可编辑。
- 导入或解析成功后清空旧问题、回答、提交状态、评价和保存提示。
- 不支持类型、空文件、文件过大、读取失败、解析失败、解析为空和扫描版 PDF 都有明确提示。
- 原始文件、文件名、文件路径或文件元数据不写入历史记录、localStorage、数据库或日志。

历史记录：

- 最终评价成功后新增本地历史记录。
- localStorage key 为 `ai-interview-sessions`。
- 新记录排在最前，最多保留 10 条。
- 新记录保存 `jobTitle`；历史列表和详情优先显示岗位名称。
- 旧记录缺少 `jobTitle` 时，标题 fallback 到岗位信息摘要，再 fallback 到“未命名岗位”。
- 历史列表支持单条删除，删除前需要确认；删除当前选中项后应自动选中剩余第一条，删空后显示空状态。
- 历史页支持清空全部本地记录，清空前需要确认。
- 历史页左侧列表支持收起/展开；左侧列表只显示岗位名称、时间和分数，Mock/AI 来源保留在右侧详情。
- 历史详情展示岗位摘要、简历摘要、整体评价和问答记录。
- 旧记录缺少 `generationSource` 时仍可展示。

Mock 流程：

- Mock 问题和 Mock 评价只在开发环境显示。
- Mock 按钮由用户显式点击，不自动替代真实 AI。
- Mock 评价复用历史保存机制，`generationSource` 标记为 `mock`。
- 真实 AI 流程仍走后端 API 和正式 prompt。

## PR 前检查

- `git status --short`
- `git diff --check`
- 能构建时运行 `npm run build`
- 不启动 dev server，除非用户明确要求
- 最终回复说明已运行和未运行的检查
