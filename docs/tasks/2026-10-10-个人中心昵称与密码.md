## 目标与范围

为邮箱密码注册增加必填昵称，并让个人中心总览与账户页显示该昵称。账户页支持修改昵称和登录密码；昵称存入 Supabase Auth `user_metadata`。

手机号绑定、短信发送、头像修改、OAuth、资料表和其他账户设置不在本轮范围内。手机号条目保持当前只读状态展示。

## 验收标准

- 注册要求填写昵称，仅接受汉字和英文字母；汉字按 2 个长度单位、英文字母按 1 个，最多 14 个单位。
- 已有无昵称账号显示“面试用户”；修改昵称后账户页与个人中心总览显示更新值，重新登录后仍保留。
- 密码行始终只显示固定 `********`；可验证当前密码、确认两次新密码一致后修改，取消会清空表单输入。
- 密码和 Supabase session token 不写入 metadata、日志或浏览器持久化存储。
- 桌面和手机布局、键盘焦点、加载和错误状态可用；构建和差异检查通过。

## 已确认计划

- 从当前 `main` 建立 `codex/profile-account-settings` 分支，沿用 Supabase Auth 与现有浏览器 client，不安装依赖或新增数据库表。
- 注册调用 `signUp` 时把昵称写入 `options.data.nickname`；昵称规则集中在项目内部辅助模块，供注册、账户编辑和服务端展示共用。
- 账户页服务端读取当前用户；可编辑部分在客户端调用 `auth.updateUser` 更新 metadata 或密码。修改密码前以当前邮箱和输入的当前密码调用 `signInWithPassword` 验证。
- 本轮不启用 Supabase Phone MFA 或任何短信服务，原因是该方案存在固定 MFA 附加费和短信按条费用。
- 完成自查后交独立 session 审查；功能验收方式由用户在实现和审查后决定，最后提供 PR 标题和描述供用户手动合并。
