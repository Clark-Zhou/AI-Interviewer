## 2026-10-10 验收中发现的账号状态问题

- 用户在 Codex 内置浏览器登录后，主页一度显示未登录，进入面试区又被带回登录页。同一浏览器随后刷新主页可显示已登录，说明浏览器会话并未丢失。
- 本机开发日志出现 `AuthRetryableFetchError: fetch failed`。原实现将服务端读取 Supabase 失败时的空用户直接当成未登录，主页误显退出，proxy 和布局误重定向。
- 修复方向：登录后确认服务端会话；服务端遇到可重试的网络/服务错误时显示可重试状态，只有明确无会话时才跳转登录。
- 实施结果：登录后通过 `/api/auth/session` 核对服务端会话与本次账号一致；主页、proxy、面试区布局及个人中心将可重试的 Supabase 错误与未登录分开处理。未改变 Supabase Auth 登录方式或存储。
- 浏览器实测：同一内置浏览器先出现“暂时无法确认登录状态”，刷新后无需密码即可显示已登录并进入工作台。Mock 问题与评价生成后标题获得焦点；390px 手机宽度下评价标题、分数和底栏可见。云端历史保存和重试连续失败；新标签页曾再次出现账号服务不可用，手机问题定位、真实 AI 语气及其他失败路径仍未完成验收。
- 独立复审：审查对象为相对 `075c4f1` 的认证修复未提交 diff，随后以 `8571d59` 提交；独立 session 提出的昵称二次读取、408/429 分类、旧账号会话比对及无效 JSON 的 400 协议问题均已修复。最终复审通过；功能验收缺口仍保留。
