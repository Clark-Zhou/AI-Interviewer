## 目标与范围

为受保护的面试区加入五入口导航：简历仓库、历史记录、工作台、数据和分析、个人中心。桌面顶部、手机底部；工作台居中强调。工作台只提供新建面试入口，历史记录沿用原有本地数据，另建三个简洁页面骨架。新面试有未保存内容时，离开前提醒。

非目标：简历仓库存储、数据统计、个人资料、草稿恢复、后端 API 或依赖变更。

## 验收标准

- 五入口在所有受保护页面可见，顺序、高亮和工作台强调正确；手机底栏不遮挡内容。
- 工作台进入现有新面试；历史记录原功能和 localStorage 数据保持可用；三个新页面可进入且无未实现控件或开发进度提示。
- 未完成面试离开时可取消或确认；成功保存后可直接离开，失败或再次编辑后继续提醒；覆盖页面链接、返回、刷新、关闭和登出。
- 未登录仍被保护，构建通过；使用 Mock 流程检查核心交互。

## 已确认计划

沿用用户本轮确认的五入口导航计划。使用共享的受保护区域外壳承载账号条和导航；新建面试仍在 `/interview/new`。页面间使用原生跳转配合 `beforeunload`，登出单独确认。简历仓库仅保留通往新面试的入口，其他两个骨架页面只展示标题；三页均不显示“即将开放”等信息。

- 问题：`components/AuthStatusBar.js:90-105` 在展示未保存面试的登出确认后，将焦点移到“取消”按钮，但未把说明丢失内容的段落关联到确认组或按钮。屏幕阅读器聚焦按钮时可能只读出“确认登出 / 取消”，不告知继续登出的后果。为警告文本提供 `id`，并用 `aria-describedby` 关联确认组或“继续登出”按钮；复核焦点移动后的朗读内容。

- 已核对：共享布局和 `proxy.js` 的登录保护、五入口顺序及当前区域标记、原生页面链接和 `beforeunload`、登出页面内确认、本地历史组件及存储键未变更、保存成功快照与保存失败或再次编辑后的提醒状态、桌面和手机底栏样式，以及受影响文档与任务范围。
