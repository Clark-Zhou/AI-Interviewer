# 复用现有 Vercel 项目发布受邀内测

- 状态：进行中
- 计划确认：用户于 2026-10-15 明确批准
- 比较基准：`928e80b`（`main`）
- 相关专题文档：[运行说明](../WORKFLOW.md)、[项目状态](../STATUS.md)

## 目标与范围

复用现有 Vercel 项目与网址，准备受邀内测：保护线上入口、限制注册和 AI 调用、明确真实材料处理方式，并使用独立 Supabase 项目进行预览验收。

非目标：迁移旧 Supabase 数据、在未经线上验收时开放邀请、仅靠 Git tag 代替部署验证。

## 验收标准

- 正式网址及 API 受到访问保护，部署提交与环境变量已核对。
- AI 接口仅供登录用户使用，每账号每天最多调用 20 次；并发请求不能绕过限制。
- 仅受邀邮箱可注册；真实材料告知可见；异常与大请求得到安全响应。
- 独立 Supabase、预览部署和两个受邀账号的真实流程、隔离与失败重试完成线上验收。
- 构建、差异检查和独立 session 审查通过；`alpha.2` tag 与生产部署提交一致。

## 已确认计划

按用户批准的《复用现有 Vercel 项目发布受邀内测》执行：先核对并保护当前部署，再在新分支实现安全边界及告知，配置独立 Supabase、预览验收，审查通过后记录版本、合并及核对生产部署。发现阻断问题时停止邀请并递增后续 α 版本。

## 实施与验证结果

- Vercel 当前生产部署来源为 `main` 的 `928e80b`。原保护为 Standard Protection，未覆盖正式网址；已将 Require Log In 调整为 All Deployments，后台确认保存。
- 当前 Vercel Production/Preview 环境变量列表有 DeepSeek key/model 及 Supabase URL/publishable key，未见简历仓库所需的 `SUPABASE_RESUME_API_TOKEN`。未读取任何密钥值。
- 已加入 AI 请求鉴权、输入边界、统一错误响应、UTC 每日 20 次原子额度 SQL、受邀邮箱 Auth hook SQL、文件解析及仓库上传请求流上限和真实材料告知。`npm run build` 两次通过，`git diff --check` 通过；Node 请求流检查确认正常 multipart 成功、无 Content-Length 的超限 multipart 在解析前拒绝。尚未进行云端行为验收。
- Supabase 控制台目前只有旧项目；新项目创建表单已填入 `AI-Interviewer-Invite-Beta`、关闭新表默认授权、开启自动 RLS，等待项目所有者亲自输入数据库密码并提交（浏览器操作规则要求凭据由本人操作）。尚未执行 SQL 或设置 Vercel 预览环境变量。
- 代码已提交为 `aa5c522` 并推送任务分支；GitHub 的 Vercel 检查显示预览构建成功。预览环境变量还未指向独立 Supabase，因此这只是构建结果，不是功能验收。匿名请求正式网址的本机网络连接超时，正式网址保护仍需从外部浏览器复核。
